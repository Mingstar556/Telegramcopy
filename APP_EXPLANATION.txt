1. WHAT IS THIS APPLICATION?
--------------------------------------------------------------------------------
This application is a self-hosted, multi-device web chat system that connects 
directly to a company Telegram Bot. It allows company employees / operators to 
log into a modern web interface as the bot and communicate in real-time with 
company clients who interact with the bot on Telegram.

Key capabilities:
- Employees log in with their credentials from any device (Desktop, Tablet, Mobile).
- Concurrent multi-device sessions: an employee can be logged in from their office 
  PC, home laptop, and phone at the same time without getting logged out.
- Auto-fetching conversations: upon employee login or page refresh, client chats 
  and message history are automatically fetched and synced from Telegram into the 
  local database and displayed in the web chat list.
- Two-way messaging: when an employee sends a message via the web UI, it is delivered 
  instantly to the client on Telegram; when the client replies on Telegram, the web 
  app receives it via real-time WebSocket.
- AI Chat & Conversation Summarizer: instant dialogue synthesis in the chat header 
  providing executive bullet points, customer inquiry summaries, message metrics, and 
  one-click export to private Saved Messages notes.
- Multi-Layer Security Hardening: PBKDF2 password hashing with auto-migration, media 
  upload whitelisting (25MB ceiling), Telegram webhook secret token validation, 
  login brute-force rate-limiting, and local desktop path traversal containment.
- Pure 1-on-1 customer service focus: group creation features have been removed to 
  keep the interface focused, lightweight, and clean.

3. SYSTEM ARCHITECTURE & HOW IT WORKS
================================================================================

                               +--------------------+
                               |   Client Phone     |
                               | (Telegram App User)|
                               +---------+----------+
                                         |
                                         | Telegram Bot API (HTTPS / Webhook)
                                         v
+------------------+         +-------------------------------+
|  Employee PC /   |         |      Self-Hosted Backend      |
|  Mobile Web UI   | <=====> | (Django + Channels + Daphne)  |
|  (React + Vite)  | WebSocket/REST |                        |
+------------------+         +---------------+---------------+
                                             |
                                     SQLite Database
                        (Employees, Device Sessions, Chats, Messages)

A. Multi-Device Object-Oriented Database Schema:
- EmployeeAccount:
  Represents company staff. Holds user_id, password_hash, display name, and avatar.
- DeviceSession:
  Tracks active sessions per employee. Each login creates a unique session token,
  recording device_name, device_type (desktop, mobile, tablet), IP address, and 
  last_activity timestamp. Employees can view and terminate active sessions.
- BotAccount:
  Links employee accounts to the company Telegram bot.
- TelegramUser:
  Represents clients who message the bot on Telegram (stores telegram_id, username, 
  first/last name, phone number, and avatar).
- ChatMessage:
  Stores all incoming and outgoing messages (text, voice, photo, video, stickers,
  reactions, read status, and delivery timestamps).

B. Telegram Auto-Sync Engine:
- On Login:
  When an employee authenticates via /api/auth/login/, the backend triggers an 
  automatic background conversation synchronization (sync_bot_conversations).
- On Chats List Request:
  When fetching /api/chats/?User-ID=...&sync=true, fresh updates are polled from 
  the Telegram Bot API using offset tracking to prevent duplicate messages.
- Real-Time Incoming Updates:
  Supports both Telegram Webhooks (/api/telegram/webhook/) and long-polling. 
  When a new client message arrives, it is saved to SQLite and broadcast via 
  Django Channels WebSocket group (chat_<user_id>) to all connected employee devices.
- Outgoing Message Dispatch:
  When an employee types a message in the web UI, the backend sends it via 
  sendMessage / sendPhoto / etc. to Telegram Bot API, saves it to SQLite, and echoes 
  it to all active device sessions.

5. 24/7 SERVER HOSTING & REMOTE CONNECTIVITY
================================================================================
The backend runs 24/7 on a central Server PC. Remote employees can connect from
any network (office LAN, home Wi-Fi, or mobile hotspot).

Server PC Setup:
1. Double-click START_ALL.bat (or host backend via Daphne on port 8000).
2. Choose a method to expose the Server PC to remote employees:
   - Method 1: Cloudflare Tunnel (Recommended - Zero Router Config & Free HTTPS):
     Run: cloudflared tunnel --url http://127.0.0.1:8000
     Provides: https://chat.yourcompany.com with automatic HTTPS and WSS.
   - Method 2: Router Port Forwarding:
     Forward TCP port 8000 on your router to the Server PC's LAN IP address.
     Provides: http://<PUBLIC_IP>:8000
   - Method 3: Tailscale / WireGuard VPN:
     Add Server PC and employee devices to the private VPN mesh network.
     Provides: http://<SERVER_TAILSCALE_IP>:8000

Client First-Run Automated Setup:
1. Employee launches TBOTchat.exe on their PC.
2. If first run or server not yet configured, the app immediately displays the
   server address setup form on screen.
3. Employee inputs the company server address (e.g. https://chat.company.com or
   http://192.168.1.100:8000) and clicks "Save & Connect".
4. The app runs a live health check (/api/health/), syncs config.json via
   POST /api/save_config, updates localStorage, and transitions to Login.
5. All future launches connect directly to the 24/7 server without prompting!
